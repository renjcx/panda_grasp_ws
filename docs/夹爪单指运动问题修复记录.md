# 夹爪单指运动问题修复记录

> 日期：2026-08-17
> 现象：运行 `hand_grasp_test` 时，夹爪只有一边手指在动
> 结论：Gazebo Harmonic 不执行 URDF mimic 约束（已知上游 bug），改为控制器双指同步驱动

---

## 一、问题现象

运行 `ros2 run panda_grasp_sim hand_grasp_test` 后，Gazebo 里只有 `fp3_finger_joint1`
对应的一侧手指运动，`fp3_finger_joint2` 那侧完全不动。

预期行为：两个手指是机械耦合的（mimic 关节），命令一个应该两个一起动。

## 二、排查过程

1. **检查 URDF**：`franka_hand.xacro` 中 `fp3_finger_joint2` 声明了
   `<mimic joint="fp3_finger_joint1"/>`，且 ros2_control 中只给 `finger_joint1`
   配置了 command_interface——配置本身看起来"正确"。

2. **查 Gazebo 服务器日志**（`~/.gz/sim/log/<最新时间戳>/server_console.log`），找到根因：

   ```
   [Err] [Physics.cc:1808] Attempting to create a mimic constraint for joint
   [fp3_finger_joint2] but the chosen physics engine does not support mimic
   constraints, so no constraint will be created.
   ```

3. **分析结论**：
   - URDF 的 `<mimic>` 被正确转换进了 SDF，gz-sim 也确实尝试创建约束，但运行时检查失败，
     约束**没有被创建**。
   - 这是上游已知问题：`gazebosim/gz-sim#1684`；gz_ros2_control 侧的 workaround PR
     （`ros-controls/gz_ros2_control#86`）从未合并进发布版本。
   - 当前安装的 `gz_ros2_control` 1.2.19 二进制中没有任何 mimic 处理代码（已用
     `strings`/`nm` 验证），不会替控制器补发第二个手指的命令。
   - 结果：`finger_joint2` 是一个**既没有约束、也没有命令的自由关节**，自然只有一边动。

4. **推翻旧结论**：项目文档里"bullet-featherstone 物理引擎（mimic 警告可忽略）"、
   "mimic 由物理引擎每步强制执行"的说法是错的——被忽略的那个"警告"正是根因错误。
   （实际测试确认：DART/TPE/普通 Bullet 在此 gz-physics7 构建中都没有 mimic 实现，
   bullet-featherstone 有实现符号但同样过不了 gz-sim 的运行时检查，即**当前软件栈中
   没有任何物理引擎能提供 mimic 约束**。）

## 三、修复方案

物理层放弃 mimic，由控制器同步驱动两个手指；规划层保留 1-DOF 语义。

```
物理层（Gazebo / ros2_control）：
  两个手指都是普通关节 → fp3_gripper_controller 用相同目标值同步驱动

规划层（MoveIt）：
  panda.srdf 声明 <mimic_joint> → 仍按 1 个自由度规划，
  MoveIt 生成的轨迹自动展开两个手指关节（RViz 面板拖夹爪同样生效）
```

关键改动示例（脚本）：

```python
# 修改前（只有一边动）
jt.joint_names = ["fp3_finger_joint1"]
point.positions = [0.04]

# 修改后（双指同步）
jt.joint_names = ["fp3_finger_joint1", "fp3_finger_joint2"]
pos = 0.04
point.positions = [pos, pos]
```

### 2026-08-17 实测验证结果（通过 ✓）

用 Python 订阅 `/joint_states` 完整记录 `hand_grasp_test` 执行过程，两个手指全程同步：

| 时间 | 事件 | fp3_finger_joint1 | fp3_finger_joint2 |
|------|------|-------------------|-------------------|
| t≈0s | 初始（脚本 open 前） | 0.04 | 0.04 |
| t≈4.0–5.4s | 脚本 close | 0.04 → 0.0 | 0.04 → 0.0（同步） |
| t≈7.0–8.4s | 脚本 open | 0.0 → 0.04 | 0.0 → 0.04（同步） |
| 结束 | — | 0.04 | 0.04 |

另外通过 `/fp3_gripper_controller/controller_state` 确认：JTC 对两个手指都生成了
正确的 reference 轨迹（0 → 0.04 平滑插值），`/joint_states` 的 feedback 与之吻合。

### 端到端抓取验证（通过 ✓）

运行 `pick_place_full`（Gazebo + MoveIt 全栈），`gz model -m grasp_object -p` 实测物块位姿：

| 阶段 | 物块位姿 (x, y, z) | 说明 |
|------|--------------------|------|
| 初始 | (0.600, 0, 0.115) | 桌面上的 3cm 物块 |
| 抓取完成 | (0.565, 0, **0.212**) | **被双指夹住抬升约 10cm，悬停空中** |

"物体滑落无法升高"问题（README 已知问题 #1）随之解决——主因确认就是单指抓取。
（注意：`pick_place_full` 退出时 MoveItPy 有已知的 teardown segfault，发生在
"=== Pick 完成 ===" 之后，不影响抓取结果。）

### 排查中发现的一次性事件（重要）

某次仿真中曾观察到 finger2 完全卡死在 0.0：JTC 输出正确、接口 claimed、
Gazebo 日志无错误，但物理层始终不响应 finger2 的任何命令（含负值目标）。
**重启仿真后消失，且无法复现**——判断与旧仿真进程残留 / 启动瞬态有关，
不是配置问题。若再次遇到"重启后仍单指运动"，按以下顺序排查：

1. `pgrep -af 'gz sim'` 确认没有旧 Gazebo 进程残留，有则全部 kill 后重启
2. `ros2 control list_hardware_interfaces` 确认 finger_joint2 有 command 接口且 [claimed]
3. 从 spawn 后第一条 `/joint_states` 开始记录，确认 finger2 初始值是 0.04
   （若 spawn 即 0.0 且命令无效，再重启一次）

手动验证命令：

```bash
ros2 control list_controllers            # 3 个控制器 active
ros2 control list_hardware_interfaces    # 应看到 9 个关节（7 手臂 + 2 手指）
ros2 topic echo /joint_states --once     # 应包含 fp3_finger_joint2

# 双指闭合
ros2 action send_goal /fp3_gripper_controller/follow_joint_trajectory \
  control_msgs/action/FollowJointTrajectory \
  "{ trajectory: { joint_names: ['fp3_finger_joint1', 'fp3_finger_joint2'],
    points: [ { positions: [0.0, 0.0], time_from_start: { sec: 1, nanosec: 0 } } ] } }"
```

## 六、注意事项与遗留

1. **与"物体滑落"问题的关系**：之前已知问题列表里的"物体从夹爪滑落"，主因就是
   **夹爪只有一边在动**——单指根本夹不住物块。本次修复后已实测 `pick_place_full`
   抓取成功（物块 z: 0.115 → 0.212 悬空），问题闭环。剩余"绿色方块偶尔消失"
   与轻质物体物理稳定性有关，另行排查。
2. **MoveIt 侧 URDF 保留 mimic**：`panda_moveit_config/config/panda.urdf`（move_group
   使用的 robot model）里的 mimic 标签**没有删除**——MoveIt 的语义以 SRDF 为准，两者
   声明一致（finger_joint2 = finger_joint1），无冲突；如需完全统一可后续再清理。
3. **`allow_partial_joints_goal: true` 的影响**：只含 `finger_joint1` 的轨迹（例如旧版
   本的手动命令）会被接受但只动一边。所有入口（脚本 / README 示例 / MoveIt）已改为双指。
4. **上游修复后可以回退**：若未来 Gazebo/ros2_control 版本修复了 mimic 约束
   （gz-sim#1684），可以恢复 URDF mimic + 单指配置的原始设计；本次改动集中在
   4 个配置文件 + 2 个脚本，回退成本低。
